
## فحص السجلات

- سجل التطبيق يعرض طلبات API ناجحة للمصادقة ولوحة التحكم والتقارير.
- توجد رسالة خطأ دورية من عامل الإشعارات أثناء `getDueNotifications` داخل `Timeout`، لكن نص الاستعلام مقطوع في واجهة السجل ولا يكفي لتحديد السبب.
- آخر سجل مرئي يشير إلى أن التطبيق يعمل على build منشور سابق، وليس على التغييرات المحلية الحالية.
- لم يتم فتح Environment Variables أو تعديلها لتجنب كشف أو تغيير الأسرار.

محاولة فتح مسار `/deployment` مباشرة أعادت المتصفح إلى لوحة Coolify الرئيسية بدل صفحة التطبيق؛ يلزم استخدام رابط الصفحة المستخرج من الواجهة أو إعادة فتح التطبيق ثم اختيار deployments من داخله. لم يتم تنفيذ أي تغيير.

ظهر 404 عند استخدام معرف مشروع مختصر بالخطأ. معرف المشروع الصحيح في الرابط الأصلي هو `vg04ck4swgs884kgo0cgckgo`، وليس `vg04ck4swgs884kgo`. لم يتم تعديل البيئة.

أعيد فتح التطبيق بالمعرف الكامل الصحيح وظهر التطبيق بحالة `Running`. صفحة Configuration تؤكد أن فرع Git هو `main` وأن الـ commit المنشور ما زال `2c527d0`. رابط deployments الصحيح داخل الواجهة هو `/project/vg04ck4swgs884kgo0cgckgo/environment/xc00sk4sk8sowgw0g44og0k0/application/lk40g8kc00s48gcwk8wko00c/deployment`، بينما فتح نسخة ناقصة من المعرف أدى إلى 404. لم يتم الضغط على Redeploy أو Save.

بعد فتح الرابط الصحيح، ظهرت صفحة configuration بحالة `Running` والـ commit الظاهر ما زال `2c527d0`. لم يبدأ نشر جديد في هذه الخطوة؛ السبب المرجح أن التعديلات المحلية لم تُرفع إلى GitHub بعد، لذلك لا يمكن لـ Coolify التقاطها من الفرع `main`. لم يتم الضغط على Redeploy فعليًا في هذه الجولة بسبب بقاء commit قديم ظاهرًا.
