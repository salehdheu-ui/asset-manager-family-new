# صندوق العائلة — Family Fund OS

نظام متكامل لإدارة صندوق مالي عائلي: مساهمات شهرية، سلف بجدولة أقساط، مصروفات، توزيع رأس المال على طبقات محمية، حوكمة بوضع طوارئ، وسجل تدقيق دائم — بواجهة عربية مهيأة للجوال.

## البنية

| الطبقة | التقنية |
|---|---|
| الواجهة | React 19 + Vite + Tailwind + shadcn/ui (RTL) |
| الخادم | Express 5 + TypeScript |
| قاعدة البيانات | PostgreSQL + Drizzle ORM |
| الاختبارات | Vitest (حسابات مالية + قواعد أمان) |

## التشغيل محلياً

```bash
npm install
cp .env.example .env       # ثم عدّل القيم
npm run db:push            # إنشاء/تحديث الجداول (إضافات آمنة فقط)
npm run dev                # http://localhost:5000
```

## الأوامر

| الأمر | الوظيفة |
|---|---|
| `npm run dev` | تشغيل التطوير (خادم + واجهة معاً) |
| `npm run build` | بناء الإنتاج إلى `dist/` |
| `npm start` | تشغيل نسخة الإنتاج |
| `npm test` | تشغيل الاختبارات |
| `npm run check` | فحص أنواع TypeScript |
| `npm run db:push` | مزامنة مخطط قاعدة البيانات |

## المفاهيم الأساسية

- **الأدوار**: `admin` (الوصي — كل الصلاحيات) و`user` (عضو — يرى بياناته فقط ويقدم طلبات تنتظر الاعتماد).
- **طبقات رأس المال**: صافي الأصول يوزّع سنوياً على: محمي 45٪، طوارئ 15٪، مرن 20٪، نمو 20٪ (قابلة للتعديل من الإعدادات بشرط مجموع 100٪).
- **السلف**: طلب العضو يبدأ معلقاً؛ الاعتماد ينشئ جدول أقساط يمتص قسطه الأخير فرق التقريب. السلفة المسددة بالكامل تختفي من القائمة النشطة وتبقى في التقارير.
- **وضع الطوارئ**: من صفحة الحوكمة — يجمّد طلبات السلف والمساهمات للأعضاء مع بقاء صلاحيات الوصي.
- **سجل التدقيق**: كل عملية حساسة (اعتماد، حذف، تعديل، تغيير أمين، طوارئ) تُوثّق باسم منفذها ولا تُحذف.
- **النسخ الاحتياطي**: تلقائي يومي (عند تفعيله من الإعدادات) + يدوي، ويشمل كل الجداول بما فيها سجل التدقيق.
- **العمليات المالية**: كل عملية متعددة الخطوات (اعتماد سلفة، تسجيل سداد، تصفية استثمار، إخراج زكاة) تُنفَّذ داخل معاملة قاعدة بيانات واحدة — إمّا تكتمل كلها أو لا يُكتب منها شيء.

## التطبيق والإشعارات (PWA)

النظام يُثبَّت **تطبيقاً حقيقياً** على أندرويد والآيفون: أيقونة في قائمة التطبيقات، وشاشة إقلاع، وواجهة بلا شريط متصفح — لا اختصاراً يفتح المتصفح.

- **التثبيت**: على أندرويد يظهر زر تثبيت مباشر يبني تطبيقاً مستقلاً (WebAPK)، وعلى الآيفون تظهر خطوات الإضافة من سفاري. البطاقة تظهر مرة واحدة ولا تتكرر بعد التثبيت أو التجاوز، ويبقى زر دائم في صفحة «حسابي» لمن تجاوزها.
- **شروط التثبيت**: كلها مفحوصة آلياً — شغّل `npx tsx script/check-pwa.ts https://your-host` على أي نسخة منشورة. سقوط شرط واحد (نمط عرض، أيقونة، معالج fetch) يهبط بالتثبيت إلى اختصار بلا أي رسالة خطأ، وهذا الفاحص يقول أيها سقط.
- **الأيقونات وشاشات الإقلاع** مولّدة من الشعار: `npx tsx script/make-pwa-icons.ts` و`npx tsx script/make-pwa-splash.ts`. الناتج محفوظ في المستودع، وشاشات iOS لها وسوم مطابقة في `client/index.html`.
- **لقطات نافذة التثبيت** في `client/public/screenshots` من بيانات وهمية بحتة (أسماء «فلان الفلاني» وأخواتها) — لا تظهر فيها بيانات العائلة إطلاقاً.
- **بلا اتصال**: تفتح واجهة التطبيق من المخزن المحلي، لكن **لا تُخزَّن أرقام الصندوق إطلاقاً** — أي بيانات معروضة هي بيانات حيّة من الخادم.
- **الإشعارات** تعمل بلا إعداد: يولّد الخادم مفتاحَي VAPID عند أول إقلاع ويحفظهما في قاعدة البيانات، فيثبتان بعدها ولا تبطل اشتراكات الأجهزة عند كل نشر. ومن أراد مفاتيح بعينها وضعها في `VAPID_PUBLIC_KEY` و`VAPID_PRIVATE_KEY` و`VAPID_SUBJECT` فتُقدَّم على المولَّدة.

  يفعّل كل فرد الإشعارات من صفحة «حسابي»، ويرسلها الوصي من صفحة «الإشعارات» — فوراً أو مجدولة، للجميع أو لفئة أو لفرد.

- **التذكيرات التلقائية**: يفحص النظام كل ست ساعات ويذكّر كل عضو بقسطه الذي اقترب أو تجاوز موعده، وبمساهمة شهره إن لم تُسجَّل قبل يوم 26. التذكير يذهب **لصاحب الالتزام وحده**، ولا يتكرر لنفس القسط أو الشهر مهما أُعيد تشغيل الخادم. ويوقفه السداد فوراً.

> على الآيفون لا تصل الإشعارات إلا بعد **تثبيت التطبيق** على الشاشة الرئيسية (قيد من iOS نفسه منذ 16.4).

## ملاحظات نشر

- `SESSION_SECRET` إلزامي في الإنتاج.
- **مزامنة المخطط تلقائية**: عند كل إقلاع يُنشئ الخادم ما ينقص قاعدة البيانات من جداول وفهارس وأعمدة — لا طرفية ولا خطوة يدوية بعد النشر. والمنفَّذ **إنشاء محض**: لا حذف ولا تغيير لقائم، ويحرس ذلك اختبارٌ يرفض أي عبارة هادمة في المخطط المولَّد. تعطيلها بـ `SCHEMA_SYNC=off`.
- ما يهدم — حذف عمود، تضييق نوع، إعادة تسمية — يبقى خارج المزامنة ويُنفَّذ بـ `npm run db:push` بيد صاحبه.
- بعد أي تعديل على `shared/schema.ts` أعد توليد ملف المخطط: `npx tsx script/make-schema-sql.ts`.
- CI (GitHub Actions) يفحص الأنواع والاختبارات والبناء وثغرات الاعتماديات على كل تحديث.
